### Refactor suggested for testability?
- **None.** The service is testable as-is.
- **Note 1**: The service uses `_dbContext.Entry(schedule).Property("RoomId").CurrentValue = roomId` — this is EF shadow property assignment. With a real DbContext (in-memory), this is allowed; `Entry(entity)` always returns a non-null `EntityEntry`. However, we should be careful: `_dbContext.Set<DoctorSchedule>().Where(...).ToListAsync()` is the actual query path inside `FetchRoomOccupancyAsync`. In tests we'll use a real `AppDbContext` (in-memory) so shadow property queries work as long as we set `RoomId` on the seed entity via the same shadow-property API.
- **Note 2**: We must use a real `AppDbContext` with in-memory DB so `_dbContext.Set<DoctorSchedule>()` works.
- **Note 3**: `_scheduleCommandRepo.CreateAsync(schedule)` is mocked to return `Task.CompletedTask`; the service ignores the return value.
