### MockQueryable / Mocking notes
- The `_clinicRepository.FindByCondition(c => c.Id == clinicId && c.IsActive).FirstOrDefaultAsync()` and `_feedbackRepository.FindByCondition(...).CountAsync()` patterns **may not** apply Where predicates reliably in MockQueryable 10.0.5 (based on observed behaviour in earlier tasks).
- Strategy: For the **happy path** tests, seed only the matching rows so MockQueryable returns the right list anyway. For the **throwing branch** (`FirstOrDefaultAsync` returns null), seed an empty list.
- For `CalculateTotalPages`, `NormalizePaging`, `BuildResponse`, `CreateSuccessResponse`, use reflection to invoke directly with controlled inputs/outputs — zero dependency on repo behaviour.
- For `FetchFeedbacksAsync`, seed multiple rows; MockQueryable will honor `OrderByDescending`, `Skip`, `Take`, `Select`, `ToListAsync` correctly. The projection accesses `f.Patient.FullName` via the in-memory navigation property.
